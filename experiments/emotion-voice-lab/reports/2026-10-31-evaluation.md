### 重測設計

目標為「看到熟客時帶笑意的親切歡迎」，不是更大聲、更用力的喊話。

1. 保留原句、同一參考聲音、語速 1.0，測試 requested strength 0.35／0.50／0.65（重複基準），只改強度；數值是實驗設定，不是已證實的最佳解。
2. 使用同一句中性台詞「你來了，我剛好在這裡。」比較自然／開心／生氣，開心與生氣皆用 requested strength 0.50。不能只換成「太棒了」等正面台詞就宣稱原句問題已解決。
3. 先盲聽隱藏標籤，再判斷情緒、自然度與音色一致性；保留失敗樣本。若向量模式仍無法區別，再試已獲授權的獨立開心情緒參考錄音。
4. 記錄參考音檔 SHA-256、完整請求、API／模型版本與後端轉換。`emo_random=false` 不保證整個生成程序完全可重現；無固定 seed 支援時，需重複生成檢查變動。
5. 服務額度不足就停止，不更換帳號或 IP 規避限制。沒有新的聽評結果前，開心版本維持未通過。

## 同步修正

- 禁止重用輸出資料夾，避免覆寫舊 WAV 或成功 manifest；重複執行在呼叫 API 前即拒絕。

- Python 和 JavaScript 拒絕錯誤型別、空台詞、無效值及重複 ID。
- 上一輪本機測試：16 項 Python + 6 項 Node 測試全數通過；GitHub CI 檢查同一組測試。此段不是新一輪重測音檔的品質結果。

## 邊界

本次驗證的是官方示範模型，不是 AutoIP API，也不是自行部署的 vLLM 服務。沒有呼叫 AutoIP、沒有租用付費 GPU，沒有上傳使用者個人錄音。

示範聲音僅作技術評估，尚未確認可作正式遊戲角色或商用。臺灣口音、發音正確性、情緒自然度與同一角色的音色一致性尚未完成正式多人聽評，不能宣稱可直接上線。第一位使用者已指出開心像生氣，該項明確維持未通過。
