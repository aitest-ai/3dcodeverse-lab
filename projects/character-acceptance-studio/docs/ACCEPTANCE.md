# 第一版驗收狀態與下一階段

本版是可操作的端到端驗收工作室與兩位角色的**修正候選**，不是已通過美術的正式人物庫。所有清單、觀察匯出與取用 lock 保留 `art_approved=false`、`game_ready=false`。沒有把程式、離線或瀏覽器通過提升成人工美術或手機通過。

## 實際做出的內容

- 實際 Three.js 網頁：載入進度/錯誤與同版重試、完整 SHA-256、待機/走跑、暫停/30fps逐格/速度/循環、八個鏡位、骨架與配速網格、同鏡位 A/B、PNG/WebM、分區觀察 JSON。
- Harbor 新母檔與 GLB：沿用 Quaternius 授權動作，烘焙接地與步速候選；袖端切成乾淨邊界，重做有厚度且可編輯的袖口；肩帶依**實際外套三角形**取樣，重做最高4個正規化權重。原始來源、拓樸與舊袖帶保留在 sources，不覆蓋。
- V29 騎樓阿伯：以實際53骨 A-pose、父子關係、骨長、骨軸/roll 與65骨來源建立獨立設定，重新烘焙骨架動作，不搬 accessor/inverse bind。腿長適配比約0.865689；保留原14表情與不同衣鞋。
- 阿伯瀏覽器材質缺陷：原 V29 皮膚/眼/牙舌以 BLEND 匯出，使內部眼牙穿在臉前。本次 candidate 改不透明，鞋保留原 alpha 並明確匯出 MASK0.5；原 packed影像沒有改寫。前後對照 A保留失敗，B修正；baseline 是本次重定向初稿，不冒稱原 V29 已有走跑。
- 每角色母檔、GLB、原尺寸貼圖、骨架設定、來源/授權、修改清單、版本與 SHA；可重建及固定 ID+版本+雜湊取用。原版與失敗證據沒有混進成品標籤。

## 分開記錄的驗收

最終機器可讀證據以 `evidence/program-qa.json`、`browser-qa.json`、`blender-cold-read.json`、`frame-catalog.json` 為準。若檔案缺少，該項就是未完成，不能由這份說明推論通過。

| 類別 | 本版範圍與限制 |
|---|---|
| 程式/檔案 | 解析真 GLB/accessor/finite數值/蒙皮/內嵌圖、完整SHA/bytes、角色與manifest一致、真正動作位移、循環接縫門檻、錯版/錯hash/覆寫/候選正式取用拒絕；通過只屬相應程式結構 |
| Blender | 官方SHA核對5.2.3背景執行；原始/新增母檔冷讀、實際 packed pixel解碼、GLB重新匯入與骨骼位移；本輪新增候選**沒有離線渲染驗收**，來源舊 Cycles 圖不充當新候選證據 |
| 瀏覽器實際操作 | Chromium + SwiftShader 真WebGL2、原GLB與原生WebCrypto。實際操作與負面失敗/重試分開記錄；圖像/影片來自真WebGL，非mock、離線渲染或替身人物 |
| 手機真機 | **未測**。390×844僅桌面瀏覽器視窗版型與WebGL檢查，不是Android/iOS、觸控、溫度/電量或GPU效能 |
| 人工美術 | **未核准**。AI看過代表畫面並發現/修正具體問題，不代替使用者對完整動態自然度、角色身份與服裝輪廓的核准 |
| Godot/Unity/Unreal/地圖 | 本版新增資產**未測**。PR137原Godot證據屬來源版本，不能沿用為本版。沒有更新基隆河、北海道、洞爺湖或其他網站 |

`evidence/frames/` 每組是8個**實際瀏覽器時間取樣**，前/側/背/肘袖，各自同鏡位A/B；`videos/`由這些序列組成，保留動畫原時長並重複循環。它們不是即時30fps錄屏。A 在左、B 在右。另有瀏覽器介面6秒計時錄製的WebM（FFprobe實際時長約5.50秒），軟體繪圖可能掉格，不能作硬體benchmark。

## 失敗候選的保留方式

`evidence/history/`明確保留：Blender新版未選Action Slot造成的靜態初稿、父骨未逐層更新造成約1m循環跳差的失敗、原V29 WebGL透明排序臉部失敗及修正前資料。它們是拒收/診斷證據，不是成功版本。V31已成功建置的Cloth/衣襬候選與先前失敗分開保留在原PR，本版未將其標成美術成品。

## 下一階段順序

1. 使用者在工作室實看 Harbor Walk/Run 的前側後/肘袖，再看阿伯同動作；逐部位匯出觀察，先決定哪段動作能進一步精修。
2. 完成支撐腳鎖定與循環、起停、左右旋轉步，再烘焙並重驗；保留跑步飛行期，不用每幀拉到地面掩蓋問題。
3. 手動修 Harbor 胸/領/腋鬆量與肩帶縫合，再逐阿伯身形修肩腰臀、褲襠/膝與權重；原貼圖解析度保留。
4. 收到V111/彩虹橋確切來源後逐項比較；依美術結果採用，不能整條分支混入。
5. 以真正手機及指定地圖/第二引擎做獨立實測，再另發正式資產版本；不得直接把本版候選旗標改成已核准。

## AI動作工具評估界線

本機約17GiB RAM，CPU渲染，未偵測NVIDIA GPU/`nvidia-smi`；Blender4.3.2原已安裝，為讀新母檔另裝經官方SHA驗證的5.2.3。沒有載入大型動作模型，沒有自行訓練。Kimodo/NVIDIA真人API/其他模型的實際權重授權、硬體、帳戶/額度仍未完成核對，列後續候選，未輸入真人影片/金鑰、未申請權限或付費。本版先用已明確CC0的現成動作完成流程。

完整單檔HTML由localhost載入同樣原生SHA/WebGL流程；雲端瀏覽器的 file:// 導覽被 ERR_BLOCKED_BY_ADMINISTRATOR 拒絕，沒有關閉政策或繞過。直接下載/雙擊模式與使用者本機下載保存位置未實測。

## 本輪量測數字（不等於美術核准）

- 本地真 Chromium/WebGL2 19項操作/失敗恢復檢查通過；0個未捕捉頁面錯誤。唯一console HTTP404來自刻意的缺模型負面測試。
- 5份母檔冷讀與實際packed pixel解碼、2份新GLB重新匯入及真實Walk骨骼位移通過。
- 30fps取樣：兩位Walk最低鞋底均約+4mm。Harbor Walk最大關節首尾差17.81mm，阿伯Walk約0mm；這只是指定關節的循環端點差，不是所有頂點連續無跳差。
- 配速下的stance足部平均殘差：Harbor Walk約0.03954m/s，阿伯Walk約0.02741m/s；分類是鞋底低於每腳最低值+23mm且前向腳速>0.1m/s，樣本/門檻詳program-qa。不能把這些非零數字稱零腳滑。Run保留雙腳離地時段。

來源限制：PR137在先前製作時已移除衣物覆蓋的人體幾何；本輪未再刪人體來掩蓋新穿模。故Harbor母檔並非完整未遮蔽的解剖人體，全面衣服/身體碰撞審查仍須取回source-lock所指的完整CC0基底。阿伯來源保留13,380原生人體頂點。

## 第二種身形：哪些能共用、哪些仍須個別處理

| 項目 | 共用結果 | 必須個別處理 |
|---|---|---|
| 動作語意與時間 | 同一CC0 Idle/Walk/Run來源、米制、前向語意及30fps烘焙 | 65→53骨映射、A/T參考姿勢、每骨roll、父子關係、腿長/骨長比例、pelvis位移重新計算；不共用bind或動畫accessor |
| 配速/接地 | 相同量測與兩骨IK演算法 | 每位實際鞋底網格/接觸時段與速度各自量測：Walk約0.890m/s與0.807m/s；不是人物等比縮放 |
