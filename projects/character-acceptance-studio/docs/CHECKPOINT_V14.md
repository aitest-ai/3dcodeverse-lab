## 母檔與驗證

每套完整母檔 50 骨、18 骨架 action、3 root action。新動作各 500 條原生曲線，WalkWorld 每條 375 keys，StartWalk／StopWalk 每條 1123 keys。**不能用一般 keyframe_insert 逐點插入或隨後呼叫 FCurve.update() 重建密集曲線**：Blender 會合併相距 0.01 frame 的點。使用 `v14/native_bake.py` 整批寫入已排序資料，冷開再檢查鍵數。

冷開四套 A/B 母檔，各 21 個片段／時間探針；與瀏覽器比對全部 6548 身體頂點。母檔重匯最大曲線 component 差約 `3.07e-6`；故意修改幾何或 root 曲線均被拒絕。GLB 精確 SHA 重建與母檔跨機儲存 SHA 是不同事情，後者依當次檔案記錄。

標準管線以 **480 Hz** 檢查整段 9.333333 秒／5.6 m 起停序列，包含一般 240 Hz 關鍵格之間的中點。門檻為無穿地、支撐蹄整片漂移 <1 mm、預定支撐至少兩蹄、首尾四蹄；程式通過不等於物理動態平衡。細部數值、實際取樣數與冷開誤差以交付包內 `acceptance-summary.json` 為準。

驗收資料包含 560 張實際 Chromium A/B 連續畫面（WalkWorld／StartWalk／StopWalk 的前、側、後、前後足與俯視，以及完整序列和三個接縫），兩段 WebM，以及軟體錄影的編碼長度與序列終點紀錄。手機 390px 桌面排版不代表真機；動畫影片可能掉格／時間壓縮。

程式、原生冷開、瀏覽器操作、解壓重建分別有報告。離線渲染、人工美術、手機真機、GPU 效能、完整碰撞、真正 COM／地面力及遊戲內驗收未測。軀幹投影仍是四 shoulder 骨頭平均值，不能據此宣稱動態平衡。
