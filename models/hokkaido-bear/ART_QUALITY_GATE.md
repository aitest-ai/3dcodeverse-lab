# 北海道木雕熊｜3DCodeVerse 監工機制（2026-10-21 啟用）

**目前狀態：REJECTED / 未通過精緻度驗收。** 此儲存庫的 `latest`、`pbr-latest`、`baked-pilot` 都是歷史技術測試，不代表可交付的美術完成品。新工作流程不會自動把未達標的新模型覆蓋為正式發布版。

## 驗收標準（1–5 分）

每個版本必須用 **實際 GLB 渲染** 的正面、側面、斜前方等多個角度進行審查：

1. 熊類頭身比例、肩峰、臀部及可辨認的木雕熊輪廓；
2. 臉部頭骨、眼窩、耳、鼻、吻部及張口結構；
3. 鮭魚造型、頭尾鰭、與熊嘴的真實接觸咬合；
4. 木材色澤、鑿痕方向、木紋與 PBR 質感；
5. 四足、腳掌、腳趾與沒有懸空的爪部；
6. 多角度視覺一致性及清晰渲染。

**放行門檻**：六項平均 ≥ 4.0／5；每項 ≥ 3.0；無 blocker／critical 缺陷；審查檔必須綁定**該版 GLB 與所有審查預覽圖的 SHA256**，防止拿舊圖片替新模型驗收。外觀評估目前需要真正的人工或有視覺能力的 AI 審查；程式本身的影像熵、解析度與 GLB 通道檢查不能代表雕塑精緻度。

## 分工

- **自動技術檢查**：GLB 2.0 檔案結構，PBR／法線／AO 通道（材質版本），兩個實際渲染圖的尺寸與資訊量；產生機器可讀報告。
- **視覺監工**：確認實際熊類解剖和特徵，指出視覺缺陷並給出每項分數。需要新版本的新雜湊審查；拒絕版本不得只靠修正 JSON 分數核准。
- **品質閘門**：`supervisor_quality_gate.py` 對缺少審查、新模型雜湊不一致、重大缺陷或低於門檻一律回傳非零，GitHub Actions 的 `publish` 工作會被跳過。
- **退件留痕**：`reviews/hokkaido-bear/baked-pilot.visual-review.json` 和每次執行的 `art_supervisor_report.json` 是可追溯的紀錄，保留出問題的候選 GLB，不把退件偽裝成成功的美術作品。

## 目前對照版本

最新人工審查：`baked-pilot`，**1.17／5，退件**。

- 黑色突起像鈕扣眼，沒有正確的熊臉細節。
- 鮭魚過於簡化，與張嘴咬合結構不合理。
- 背部像機械壓模的重複格紋，不像傳統日本木雕刀痕。
- 腳掌和爪部顯得方塊化或像細鐵線，局部懸空。
- 整體沒有傳統深棕木雕的材質光澤和刀削面。

## 工作流程

1. 修改 `tasks/hokkaido-bear/model.py`，先處理**輪廓與解剖**，再處理材質。
2. 執行官方 3DCodeVerse Harness 的 build / measure / render（AI 自動建模代理目前未啟用）。
3. 高低模、UV、Cycles 烘焙並保留可重現的 GLB、貼圖、量測與多視角預覽。
4. 取得新版本 GLB／渲染 SHA256，先用視覺監工檢查並寫入版本限定 review。
5. 執行 `Hokkaido Bear Art Supervisor`。只有技術與藝術審查同時通過才允許 `publish`。

**不要**：把 2K／4K 貼圖存在、三角面很多或 Blender 匯出成功當作「精緻度達標」；拿 AI 生成的漂亮參考圖片冒充 3D 模型渲染；未檢視結果就向使用者宣稱完成。
